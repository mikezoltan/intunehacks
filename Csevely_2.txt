
Szeretném látni egy kliens hibrid join folyamatát és intune enrollmetjét ez első lépéstől kezdve úgy, hogy lássam az összes urlt, lépésről lépésre egészen addig a pontig, amikor sikeres az intune regisztráció
Egy hibrid Azure AD join + Intune automatikus enrollment folyamata nagy vonalakban így néz ki: az AD‑ban lévő gép hibrid módon csatlakozik Entra ID‑hoz, a GPO elindítja az MDM (Intune) auto‑enrollmentet, a kliens felveszi a kapcsolatot az MDM URL‑lel, hitelesít, majd sikeres regisztráció után megjelenik az Intune‑ban.

Az alábbi folyamatot Windows klienst feltételezve írom le, manuális és GPO‑alapú (IT által kényszerített) hybrid join + Intune enrollment nézőpontból, az URL‑ekkel és ellenőrzési pontokkal.

Előfeltételek (tenant, licenc, beállítások)
Microsoft Entra Connect (vagy Cloud Sync) szinkronizálja az on‑prem AD felhasználókat és gépeket Entra ID‑ba.

A felhasználónak van Intune (Microsoft Intune / EMS / M365) licence.
​

Intune admin centerben be van kapcsolva az automatikus MDM enrollment Entra felhasználók számára:

URL: https://intune.microsoft.com → Tenant administration / Devices rész → MDM user scope / MAM user scope.

A kliens Windows gép domain joined az on‑prem AD‑ba (klasszikus tartományi join).
​

Ellenőrzés kliensen (parancssor, rendszergazdaként):

dsregcmd /status – kezdetben: DomainJoined = YES, AzureAdJoined = NO (vagy HybridAzureADJoined = NO), MdmUrl üres.
​

1. Hibrid Azure AD join folyamata (gépfiók – Entra ID)
A hybrid join általában már a gép AD‑ba csatlakoztatása és a szinkronizálás után automatikusan történik.

Folyamat (összefoglalva):

Gép domain join az on‑prem AD‑hoz, majd reboot.

A gépobjektum szinkronizálódik Entra ID‑ba (Entra Connect).
​

A kliens Windows bejelentkezéskor kapcsolatba lép Entra ID‑val, és létrejön a hibrid Azure AD join állapot (eszközidentitás Entra ID‑ban).

Ellenőrzés:

dsregcmd /status kimenetben:

Device State alatt: DomainJoined = YES, AzureAdJoined = YES vagy HybridAzureADJoined = YES.
​

Entra ID portál: https://entra.microsoft.com → Devices → All devices, ott látszik a gép Hybrid Azure AD joined státusszal.
​

2. GPO – automatikus Intune (MDM) enrollment bekapcsolása
A tipikus, IT által kényszerített hibrid join + Intune enrollmenthez GPO‑t használsz.
​

Nyiss egy GPMC‑t (Group Policy Management) a domain controlleren.

Hozz létre egy új GPO‑t (pl. „Enable MDM auto enrollment for Hybrid devices”).
​
​

Szerkesztéskor állítsd be:

Gép‑ vagy felhasználó szinten (gyakori: User Configuration):

Útvonal:

Computer Configuration vagy User Configuration → Policies → Administrative Templates → Windows Components → MDM

Policy: Enable automatic MDM enrollment using default Azure AD credentials.
​
​

Állítsd Enabled‑re, a legördülő listában válaszd ki a felhasználó scope‑ot (pl. User credential‑based).
​

Linkeld a GPO‑t a megfelelő OU‑ra (felhasználókat vagy gépeket tartalmazó OU).
​

Kliensen:

gpupdate /force futtatása, majd újraindítás vagy kijelentkezés/bejelentkezés.
​
​

3. Kliens oldali hibrid join + MDM enrollment – háttérfolyamat
Amikor a feltételek adottak (hibrid join, licenc, MDM auto enrollment policy, felhasználó bejelentkezik), a Windows kliens a háttérben elindítja az MDM enrollmentet.

Lépések a kliensen:

A felhasználó bejelentkezik domain accounttal (szinkronizált Entra ID user).
​

A hybrid joined gép Entra ID‑val kommunikál, ellenőrzi a felhasználó licencét, és MDM authority‑t (Intune).

A „Enable automatic MDM enrollment” GPO miatt a Windows MDM kliens felveszi a kapcsolatot az Intune MDM URL‑lel:

Tipikus MDM URL: https://enrollment.manage.microsoft.com/EnrollmentServer/Discovery.svc és kapcsolódó endpointok.
​

A gép/ felhasználó egy Entra ID tokennel autentikál az Intune felé (modern auth, OAuth2/OpenID Connect).
​

Intune eszközregisztráció: létrejön az eszközobjektum Intune‑ban, kiadódnak a szükséges certifikátok (pl. MDM push cert, SCEP/PKCS tanúsítványok, ha konfigurálva vannak).

Megalakul a secure channel az eszköz és az Intune szolgáltatás között, az eszköz készen áll policyk, appok, compliance profilok fogadására.

Ellenőrizhető URL‑szinten a hálózati forgalomban (pl. F12 Dev Tools a Company Portalnál vagy netmon/Fiddler/Wireshark), de a fő publikus portál URL‑ek:

Intune admin center: **https://intune.microsoft.com**

Microsoft 365 admin center (áttekintéshez): **https://admin.microsoft.com**
​

Entra admin center: **https://entra.microsoft.com**
​

4. Manuális Windows enrollment (Access work or school)
Ha egy hybrid joined gép még nincs Intune‑ban, manuálisan is rásegíthetsz a kliensen.

Kliensen:

Settings → Accounts → Access work or school.

Válaszd a Connect gombot.

Add meg a felhasználó munkahelyi/sulinetes e‑mail címét (UPN), majd lépj tovább.

A háttérben:

Entra ID hitelesítés (MFA, feltételes hozzáférés, stb. ha van).
​

A kliens felveszi a kapcsolatot az Intune MDM URL‑lel, és végigfut ugyanaz a regisztrációs folyamat, mint automatikus enrollmentnél.

Siker esetén a „Access work or school” alatt megjelenik a szervezeti fiók, és a kapcsolat részleteinél látható, hogy MDM: Microsoft Intune.

6. Tipikus hibahelyek (röviden, hogy tudd mire figyelj)
Nincs / rossz MDM auto enrollment scope a tenantban → eszköz hibrid joined, de nem indul Intune enrollment.

Usernek nincs Intune licence → hibrid join ok, de enrollment fail.
​

GPO nincs megfelelő OU‑ra linkelve / nincs frissítve (gpupdate) → a kliens nem kapja meg az „Enable automatic MDM enrollment” beállítást.
​
​

Proxy / tűzfal blokkolja az manage.microsoft.com / windows.net / azureedge.net / microsoft.com MDM/Intune URL‑eket → enrollment time‑out.
​

Ha szeretnéd, a következő körben tudok írni egy teljes, „száraz” lab‑szcenáriót is (AD, Entra Connect, GPO, kliens lépések parancsokkal), kifejezetten hibrid join + Intune enrollment tesztkörnyezethez.

Ezt most tekintsük át úgy, hogy az sccm kezdeményezi, és lássuk az összes urlt, amit lépésről lépésre keres, meghív az enrollment folyamat.
SCCM (Microsoft Endpoint Configuration Manager, MEMCM) által kezdeményezett Intune enrollment hybrid Azure AD join környezetben tipikusan co-management setup részeként fut, ahol az SCCM kezeli a munkaterheléseket, de enrollmentkor koordinálja az Intune MDM csatornát. A folyamat Device Enrollment Manager vagy GPO alapú auto-enroll kiegészítésével indul, de SCCM client push/heartbeat során triggerelődik a háttérben.

A lépésről lépésre folyamatot hálózati trace (pl. Fiddler, Wireshark) nézőpontból mutatom, az SCCM által hívott kulcs URL-ekkel – ezek az enrollment service endpointok, discovery, auth és cert kiadás során aktívak.

Előfeltételek (SCCM + Intune co-management)
SCCM konzolban: Administration → Cloud Services → Co-management → Enable co-management, workloads shifted to Intune (pl. Compliance policies, Client apps). Licenc: E3/E5 users.
​

Hybrid Azure AD join már kész (Entra Connect sync, dsregcmd /status: HybridAzureADJoined=YES).

SCCM kliens telepítve, heartbeat aktív (minden 60 percben pollol a MP-hez: https://<yoursccm>/SMS_MP/.).

Intune tenant: MDM user scope = Some/All, Auto MDM enrollment enabled.

1. SCCM Client Heartbeat + Co-management Trigger
SCCM kliens policy frissítés (Machine Policy Retrieval & Evaluation Cycle futtatása):

Client kommunikál Management Point (MP) URL-lel: https://<sccm-server>/SMS_MP/ – letölti co-management policyket.

Policy tartalmazza az Intune enrollment trigger-t (ha workload shifted).

Client elindítja a Device Enrollment task-ot (C:\Windows\System32\DeviceEnroller.exe).

2. Hybrid Join Validáció + Entra ID Discovery
SCCM trigger után Windows Device Enrollment Service (DES) lép be:

dsregcmd /join implicit hívás hybrid state ellenőrzésre.

Első hívás: https://login.microsoftonline.com/<tenantid>/discovery.svc – Entra ID discovery endpoint, tenant metadata letöltés (openid configuration).

Hitelesítés: Client certificate vagy user token (OAuth2 flow) a szinkronizált domain userrel.

Response: MDM authority URL kiadása (Intune= https://enrollment.manage.microsoft.com/ ).

3. Intune MDM Discovery + Enrollment Request
DeviceEnroller.exe hívja:

https://enrollment.manage.microsoft.com/EnrollmentServer/Discovery.svc – MDM discovery, enrollment challenge generálás.

Client elküldi enrollment request-et (device info: HWID, serial, OS verzió).

Auth flow: https://login.microsoftonline.com/<tenantid>/oauth2/v2.0/token – device code flow vagy ROPC (Resource Owner Password Credential) a user contextben.

Response: Enrollment ID, challenge token.

4. Tanúsítvány Kérés + Secure Channel Létrehozás
Client generál CSR-t (Certificate Signing Request), hívja: https://enrollment.manage.microsoft.com/EnrollmentServer/Enrollment.svc/Enroll/Devices – PKCS#10 cert request.

Intune kiadja az MDM device certificate-et (1 év érvényesség, thumbprint tárolva registryben: HKLM\SOFTWARE\Microsoft\Enrollments).

Secure channel setup: wss://enrollment.manage.microsoft.com/EnrollmentServer/notification – WebSocket compliance/status channel nyitás (push notifications policy updates-re).

5. SCCM Client Intune Compliance Check + Policy Sync
SCCM kliens (ccmexec) pollol Location Service: https://<sccm-server>/CCM_Client CCM_POST.

Intune policy sync indul: https://manage.microsoft.com/DeviceEnrollmentWebService/service.svc/Compliance – első compliance check.

Company Portal sync (ha telepítve): https://portal.manage.microsoft.com/?portalAction=Enrollment.
